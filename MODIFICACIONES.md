# MODIFICACIONES.md

## Proyecto
**Sitio:** https://www.enriquevargas.com.mx  
**Objetivo comercial:** presentar y vender servicios de desarrollo web, menús digitales, soluciones para negocios locales y aplicaciones, con una propuesta accesible y orientada a volumen.  
**Estado actual:** sitio funcional, con propuesta comercial, precios, proyectos/demos, formulario de contacto, WhatsApp y elementos promocionales.  

---

# 1. Objetivo principal de estas modificaciones

El sitio debe estar preparado para recibir tráfico desde redes sociales y convertir visitantes que todavía no conocen a Enrique Vargas en prospectos reales.

La meta no es aparentar una agencia grande ni inventar clientes. La meta es transmitir:

- confianza;
- claridad;
- profesionalismo;
- precio accesible sin parecer improvisado;
- proceso de compra sencillo;
- ejemplos suficientes para que el visitante entienda qué recibirá;
- contacto inmediato por WhatsApp o formulario.

La propuesta de valor debe apoyarse en un modelo de trabajo estandarizado: plantillas especializadas, personalización de contenido, tiempos de entrega claros y precios competitivos.

---

# 2. Principio general de UX

El visitante debe poder responder rápidamente estas preguntas:

1. ¿Qué hace Enrique Vargas?
2. ¿Esto sirve para mi negocio?
3. ¿Cuánto cuesta?
4. ¿Qué incluye?
5. ¿Puedo ver un ejemplo funcionando?
6. ¿Cómo lo contrato?
7. ¿Qué sucede después de pagar o contactar?

Si alguna de estas respuestas requiere demasiado desplazamiento, lectura o interpretación, debe simplificarse.

---

# 3. Prioridades

## PRIORIDAD 1 — Antes de lanzar publicidad

Estas modificaciones deben realizarse primero.

### 3.1 Corregir el formulario de contacto

**Problema detectado:** actualmente el formulario puede mostrar una confirmación de éxito aunque falle la petición al servicio encargado de registrar los datos.

**Riesgo:** un prospecto puede creer que su solicitud fue enviada mientras el negocio nunca recibe sus datos.

**Objetivo:**

- mostrar éxito únicamente cuando exista una respuesta válida;
- mostrar un error claro si el envío falla;
- conservar los datos escritos por el usuario cuando ocurra un error;
- ofrecer WhatsApp como alternativa inmediata;
- evitar mensajes técnicos para el cliente.

**Importante:** esta corrección debe hacerse con el menor cambio posible y sin rediseñar todavía toda la página.

---

### 3.2 Eliminar la descarga de contrato del primer contacto

**Decisión comercial recomendada:** retirar el botón o sección que invita al visitante a descargar/generar un contrato antes de haber hablado con Enrique.

**Motivo:** pedir al usuario pensar en un contrato demasiado pronto añade fricción y puede generar sensación de compromiso antes de que exista confianza.

El recorrido recomendado es:

**Ver servicio → ver ejemplo → conocer precio → preguntar/cotizar → conversar → definir alcance → contrato/acuerdo → pago/inicio.**

El contrato sigue siendo útil, pero debe aparecer en una etapa posterior del proceso comercial.

---

### 3.3 Simplificar las llamadas a la acción

Evitar demasiadas acciones compitiendo entre sí.

Priorizar dos CTA principales:

- **Quiero cotizar mi negocio**
- **Hablar por WhatsApp**

Acciones secundarias:

- Ver demo
- Ver planes
- Conocer qué incluye

El usuario no debería tener que decidir entre muchas opciones diferentes en la misma sección.

---

### 3.4 Reforzar el mensaje principal del inicio

El encabezado principal debe comunicar una solución comercial, no solamente habilidades técnicas.

El visitante ideal es dueño de una pequeña empresa, restaurante, pizzería, negocio de comida, profesional independiente o comercio local.

El mensaje debe acercarse a conceptos como:

> Sitios web y soluciones digitales accesibles para pequeños negocios en México.

Submensaje recomendado:

> Menús digitales, páginas para negocios y sistemas sencillos listos para ayudarte a vender y recibir pedidos o citas.

No usar texto que haga parecer que el cliente necesita entender programación, React, Android, hosting o arquitectura.

---

### 3.5 Explicar por qué los precios son accesibles

Un precio bajo puede ser una ventaja, pero sin contexto también puede reducir la percepción de confianza.

Añadir una explicación breve del modelo:

- soluciones construidas sobre bases previamente desarrolladas;
- personalización de textos, productos, imágenes, colores y datos del negocio;
- proceso estandarizado;
- menor tiempo de desarrollo;
- esto permite ofrecer precios accesibles.

No presentarlo como “barato porque estoy empezando”.

Presentarlo como **un proceso eficiente pensado para pequeños negocios**.

---

### 3.6 Usar demos como principal prueba de capacidad

Actualmente no existen clientes reales suficientes para construir una sección fuerte de testimonios o casos de éxito.

No inventar:

- testimonios;
- ventas;
- clientes;
- resultados;
- logos de empresas no atendidas.

En su lugar, convertir los demos en evidencia real del trabajo.

Cada demo debería indicar claramente:

- **Proyecto demostrativo**;
- tipo de negocio;
- qué problema resuelve;
- qué puede hacer el usuario;
- botón **Ver demo funcionando**.

Ejemplo:

**Demo — Pizzería**  
Menú digital preparado para mostrar productos, precios, promociones y facilitar pedidos desde celular.

# 4. PRIORIDAD 2 — Confianza y presentación comercial

## 4.1 Crear una sección “Cómo trabajamos”

Propuesta de 4 pasos:

1. **Elige una solución**  
   Selecciona el tipo de página, menú o sistema que necesita tu negocio.

2. **Envíame tu información**  
   Logo, productos, precios, fotografías, horarios y datos de contacto.

3. **Personalizo tu proyecto**  
   Se adapta el diseño y contenido a tu negocio.

4. **Revisamos y publicamos**  
   El cliente revisa el resultado antes de la entrega final.

Esto sustituye parte de la confianza que normalmente aportarían testimonios.

---

## 4.2 Añadir una sección “Qué recibes”

Debe ser muy concreta.

Según el producto, puede incluir:

- diseño adaptable a celular;
- dominio/hosting cuando corresponda;
- botón de WhatsApp;
- información del negocio;
- catálogo o menú;
- mapa y contacto;
- configuración inicial;
- revisiones incluidas;
- soporte inicial;
- entrega publicada.

Evitar términos ambiguos como “sitio profesional completo” sin explicar qué contiene.

---

## 4.3 Añadir una sección de preguntas frecuentes

Preguntas recomendadas:

- ¿Necesito saber de tecnología?
- ¿Qué información debo enviar?
- ¿Cuánto tarda la entrega?
- ¿El precio incluye dominio y hosting?
- ¿Puedo cambiar productos o precios después?
- ¿Cuántas revisiones están incluidas?
- ¿Cómo se realiza el pago?
- ¿Qué sucede después de contratar?
- ¿Puedo ver una demostración antes?
- ¿Trabajas con negocios de cualquier parte de México?

---

## 4.4 Mejorar la presentación personal

La ausencia de una agencia grande no debe ocultarse.

La marca puede usar como ventaja la atención directa.

Recomendación conceptual:

**“Trabajas directamente conmigo, desde la cotización hasta la entrega.”**

Esto puede generar más confianza que intentar parecer una empresa grande sin respaldo verificable.

Puede añadirse una breve sección sobre Enrique, evitando una autobiografía extensa.

Debe explicar:

- atención directa;
- enfoque en pequeños negocios;
- soluciones prácticas;
- comunicación por WhatsApp;
- servicio en México.

# 5. PRIORIDAD 3 — Precios y oferta

## 5.1 Revisar inconsistencias

Se debe revisar todo el sitio para garantizar que cada producto tenga una única versión de:

- precio;
- número de revisiones;
- características;
- tiempos;
- promociones;
- soporte;
- condiciones.

Ya se detectó una posible inconsistencia en **Tarjeta Digital** relacionada con una/dos revisiones.

---

## 5.2 Aclarar paquetes similares

Debe explicarse claramente la diferencia entre ofertas que combinan Web + Android y otros paquetes Web + App con precios distintos.

Cuando dos productos parecen similares y la diferencia de precio es grande, el visitante puede pensar que existe un error o una oferta engañosa.

Cada paquete debe incluir una comparación concreta de:

- tipo de aplicación;
- funciones;
- personalización;
- publicación;
- mantenimiento;
- soporte;
- propiedad/entrega;
- limitaciones.

---

## 5.3 No competir únicamente por precio

La comunicación no debe ser:

> Soy el más barato.

Debe ser:

> Tengo soluciones ya estructuradas para pequeños negocios, por eso puedo ofrecer una implementación profesional a un precio accesible.

La investigación comparativa de precios de competidores se realizará en una fase separada antes de modificar los precios actuales.

---

# 6. PRIORIDAD 4 — UX visual

## 6.1 Reducir exceso de efectos

El estilo oscuro, neón, degradados y animaciones puede mantenerse como identidad, pero debe revisarse la cantidad de movimiento y estímulos simultáneos.

Objetivo:

- mantener personalidad;
- aumentar legibilidad;
- hacer que precios, demos y CTA destaquen más que las animaciones;
- evitar que el sitio parezca una demostración técnica en lugar de un negocio que vende servicios.

---

## 6.2 Jerarquía visual

Por cada pantalla/sección debe existir una acción dominante.

Orden recomendado:

1. título;
2. beneficio;
3. evidencia/demo;
4. precio o condición importante;
5. CTA.

---

## 6.3 Mobile first

La mayoría del tráfico de anuncios de Facebook/Instagram y WhatsApp probablemente llegará desde teléfono.

Revisar especialmente:

- tamaño de títulos;
- botones;
- tarjetas de precios;
- espacios verticales;
- ancho de formularios;
- navegación;
- velocidad;
- botones flotantes;
- cantidad de animaciones;
- facilidad para abrir WhatsApp.

---

# 7. PRIORIDAD 5 — Rendimiento y mantenimiento

Estas tareas son importantes, pero no deben retrasar innecesariamente el lanzamiento comercial si el sitio funciona correctamente.

## 7.1 Corregir ESLint

Se reportaron 5 errores de ESLint.

Objetivo:

- corregirlos individualmente;
- evitar refactors innecesarios;
- ejecutar lint después de cada grupo de cambios.

---

## 7.2 Corregir @import CSS

La compilación reporta un `@import` CSS mal ubicado.

Debe corregirse sin alterar accidentalmente la apariencia global.

---

## 7.3 Optimizar bundle

Se reportó un bundle principal cercano a **1.2 MB antes de compresión**.

Analizar posteriormente:

- lazy loading;
- importaciones de Material UI;
- Framer Motion;
- AOS;
- librerías PDF;
- componentes cargados en todas las rutas;
- división de código por páginas.

No optimizar a ciegas. Primero identificar qué módulos ocupan más espacio.

---

## 7.4 Actualizar README

El README debe reflejar el proyecto actual y no información histórica que pueda confundir futuras sesiones de Codex/IA.

Puede incluir:

- objetivo del proyecto;
- stack;
- estructura;
- comandos;
- despliegue;
- variables de entorno;
- integración del formulario;
- reglas para promociones;
- notas importantes de mantenimiento.

# 9. Regla para todas las fases

Antes de cada modificación, Codex debe:

1. identificar los archivos implicados;
2. explicar brevemente el problema;
3. proponer el cambio mínimo necesario;
4. modificar únicamente los archivos requeridos;
5. ejecutar las comprobaciones correspondientes;
6. mostrar un resumen de cambios;
7. no hacer commit ni push sin autorización explícita.

---

# 10. Criterio para considerar el sitio listo para publicidad

El sitio puede considerarse comercialmente listo cuando:

- el formulario nunca produce falsos éxitos;
- WhatsApp funciona correctamente;
- el visitante entiende qué se vende en menos de unos segundos;
- los precios y características no se contradicen;
- cada servicio explica claramente qué incluye;
- existen demos funcionales y claramente identificados como demos;
- contratar/cotizar requiere pocos pasos;
- no se obliga al prospecto a pensar en contratos demasiado pronto;
- la experiencia móvil es clara;
- no existen errores visibles de interfaz;
- el build de producción pasa;
- las páginas principales tienen una acción comercial clara.

# 12. Nota estratégica

No es necesario tener decenas de clientes para empezar a vender.

En esta etapa la confianza debe construirse con:

- transparencia;
- demos reales;
- proceso claro;
- precios comprensibles;
- contacto humano directo;
- condiciones visibles;
- buena presentación;
- cumplimiento de lo prometido.

El sitio debe vender **una solución sencilla para pequeños negocios**, no la complejidad técnica utilizada para construirla.
